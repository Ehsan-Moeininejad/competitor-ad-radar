# رادار تبلیغات رقبا (Competitor Ad Radar)

این سیستم روزی سه بار تاپ‌سایت‌های ایرانی را با موبایل و دسکتاپ مرور می‌کند و همهٔ تبلیغات آن‌ها را ثبت می‌کند: جایگاه، فرمت، شبکه، تبلیغ‌دهنده، لندینگ و آفر. بعد سه سؤال را جواب می‌دهد:

1. **رقبا چه می‌کنند؟** برای هر رقیب: سهم دیده‌شدن (SOV) در هر ورتیکال، سایت‌ها، شبکه‌ها، فرمت‌ها، نوع کمپین (ریتارگتینگ، پروموشن، اقساط، گردونه، نصب اپ…)، پیام‌ها، نام کمپین‌ها از روی UTM و امتیاز تهدید.
2. **کجا با فشار کمتر و بید کمتر وارد شویم؟** شاخص فشار و شاخص فرصت برای هر سایت و جایگاه، همراه با پیشنهاد عملی: خرید مستقیم، بید پایین در شبکه، شکاف حضور یا اجتناب.
3. **چه جایگاه، فرمت یا شبکهٔ تازه‌ای پیدا شده؟** جایگاه‌های جدید، ورود رقیب به سایت جدید، تبلیغ‌دهندهٔ تازه، شبکه‌های ناشناخته و کاتالوگ اینونتوری هر سایت.

هر شب ساعت 20 یک گزارش HTML تیره به ایمیل می‌رسد. همین گزارش روی یک صفحهٔ ثابت هم منتشر می‌شود. کل زیرساخت رایگان است و به لپ‌تاپ وابسته نیست.

## راه‌اندازی قدم‌به‌قدم (حدود 25 دقیقه، بدون نیاز به دانش فنی)

### قدم 1: شیت پابلیشرها
در شیت، دکمهٔ **Share** را بزنید و گزینهٔ **Anyone with the link → Viewer** را انتخاب کنید (انجام شده ✓).
سیستم ستونی را که آدرس سایت‌ها در آن است خودش پیدا می‌کند. اگر ستون‌هایی با نام «دسته» یا «ترافیک» داشته باشید، از آن‌ها هم استفاده می‌کند.

### قدم 2: ساخت ریپو در گیت‌هاب
1. به github.com بروید و بالا سمت راست روی **+** و بعد **New repository** بزنید.
2. در بخش **Repository name** بنویسید `competitor-ad-radar`.
3. گزینهٔ **Public** را انتخاب کنید. در ریپوی عمومی، دقیقه‌های اجرای گیت‌هاب نامحدود است.
4. هیچ تیکی (README و…) نزنید و **Create repository** را بزنید.

### قدم 3: آپلود پروژه (یک دستور)
اپ **Terminal** مک را باز کنید، این خط را کپی کنید و Enter بزنید:
```
cd ~/Documents/competitor-ad-radar && git push -u origin main
```
اگر نام کاربری و رمز خواست، همان روشی را بزنید که برای پروژهٔ research-digest استفاده کردید.

### قدم 4: کلیدها و ایمیل (Secrets)
در صفحهٔ ریپو به مسیر **Settings ← Secrets and variables ← Actions ← New repository secret** بروید و این موارد را یکی‌یکی اضافه کنید:

| نام | مقدار | لازم است؟ |
|---|---|---|
| `SMTP_USER` | جیمیل فرستنده (همان جیمیلی که دایجست با آن ارسال می‌شود) | بله |
| `SMTP_PASS` | App Password همان جیمیل | بله |
| `MAIL_TO` | `e.moeininejad@digikala.services`. برای افزودن نفرات بعدی، آدرس‌ها را با کاما جدا کنید | بله |
| `GEMINI_API_KEY` | همان کلید Gemini دایجست (از aistudio.google.com) | پیشنهادی |
| `OPENROUTER_API_KEY` | رایگان از openrouter.ai ← Keys | اختیاری (پشتیبان) |
| `GROQ_API_KEY` | رایگان از console.groq.com ← API Keys | اختیاری (پشتیبان) |
| `PROXY_URL` | پراکسی با IP ایران، مثلاً `http://user:pass@1.2.3.4:3128` | اختیاری (قدم 8) |

مدل اول (GitHub Models) کلید نمی‌خواهد و خودکار کار می‌کند. هر کلیدی که اضافه کنید یک پلهٔ پشتیبان می‌شود: اگر مدلی شلوغ بود یا تایم‌اوت خورد، سیستم بلافاصله سراغ مدل بعدی می‌رود. حتی اگر هیچ مدلی جواب ندهد، گزارش با تحلیل قاعده‌محور ساخته می‌شود.

### قدم 5: صفحهٔ گزارش
به مسیر **Settings ← Pages** بروید و در بخش **Source** گزینهٔ **GitHub Actions** را انتخاب کنید.
آدرس گزارش این می‌شود: `https://ehsan-moeininejad.github.io/competitor-ad-radar/`

### قدم 6: اجرای اول
1. در تب **Actions** وارد **ad-radar** شوید و **Run workflow** را بزنید.
2. تیک **force_report** را بزنید و Run را بزنید.
3. بعد از 40 تا 90 دقیقه (بسته به تعداد سایت‌ها)، ایمیل و صفحه آماده می‌شوند.

### قدم 7: زمان‌بندی دقیق (cron-job.org)
زمان‌بندی داخلی گیت‌هاب تأخیر دارد و گاهی اصلاً اجرا نمی‌شود. برای همین، مثل کراولر شگفت‌انگیزها، تریگر اصلی روی cron-job.org است:
1. توکنی را که برای کراولر ساختید باز کنید (github.com ← Settings ← Developer settings ← Fine-grained tokens). در بخش **Repository access**، ریپوی `competitor-ad-radar` را هم اضافه کنید. دسترسی **Actions: Read and write** باید فعال باشد.
2. در cron-job.org یک Job جدید بسازید:
   - **URL:** `https://api.github.com/repos/Ehsan-Moeininejad/competitor-ad-radar/actions/workflows/radar.yml/dispatches`
   - **Schedule:** هر روز ساعت **09:03**، **14:03** و **20:03** به وقت Asia/Tehran
   - **Request method:** `POST`
   - **Headers:** `Authorization: Bearer <توکن>` و `Accept: application/vnd.github+json`
   - **Body:** `{"ref":"main"}`

اجرای 20:03 خودش گزارش روز را می‌سازد و ایمیل می‌کند. اگر تریگر گیت‌هاب و cron-job.org هر دو اجرا شوند، اجرای تکراری خودکار رد می‌شود.

### قدم 8 (اختیاری، ولی مهم): پراکسی ایران
سرورهای گیت‌هاب در آمریکا هستند. بعضی شبکه‌ها (مثل یکتانت) ممکن است به IP خارجی تبلیغ نشان ندهند یا تبلیغ متفاوت نشان دهند.
تب **«پوشش و روش»** در گزارش سایت‌هایی را که «ادتک داشتند ولی تبلیغی نشان ندادند» علامت می‌زند. اگر این تعداد زیاد بود، یک پراکسی با IP ایران (مثلاً یک VPS ارزان ایرانی با Squid) در Secret با نام `PROXY_URL` قرار دهید. تغییر دیگری لازم نیست.

## گزارش چه تب‌هایی دارد؟

| تب | محتوا |
|---|---|
| خلاصه | تیتر روز، شاخص‌ها، هشدارها (جهش رقیب، ورود به سایت جدید، رقیب تازه، ریتارگتینگ) و اقدام‌های پیشنهادی با اولویت |
| رقبا | SOV کل و ورتیکالی، ریسک هر ورتیکال (Core مشخص است)، جدول رقبا با فیلتر ورتیکال و کارت کامل هر رقیب با اسکرین‌شات |
| فشار و فرصت | رتبه‌بندی سایت‌ها بر اساس فرصت، کم‌تراکم‌ترین جایگاه هر سایت، شکاف حضور دیجی‌کالا و نقشهٔ حرارتی جایگاه‌ها |
| کشف جایگاه و فرمت | جایگاه و فرمت تازه، ورود رقیب به سایت تازه، شبکه‌های تازه و ناشناخته، پوش و رپورتاژ، پابلیشرهای کشف‌شده و کاتالوگ اینونتوری |
| کریتیوها | کریتیوهای پرعمر (احتمالاً پربازده) و گالری امروز |
| روند ماهانه | روند ۳۰ روزهٔ سهم و تهدید هر رقیب، پایدارترین فرصت‌ها و میکس نوع کمپین |
| پوشش و روش | وضعیت اسکن هر سایت، هشدار محدودیت IP، مدل‌های استفاده‌شده و روش محاسبه |

## منطق تشخیص (خلاصه)

- **سه پروفایل:** موبایل بدون سابقه، دسکتاپ بدون سابقه، و موبایل «گرم» که قبل از اسکن از سایت رقبا و یک صفحهٔ محصول بازدید کرده است. تبلیغ رقیبی که فقط در پروفایل گرم دیده شود ریتارگتینگ است. UTMهایی مثل `retarget` یا `dpa` هم همین را نشان می‌دهند.
- **تشخیص اسلات:**
  - ظرف‌های شناخته‌شدهٔ شبکه‌ها (یکتانت، مدیااد/تپسل، ادیوری، صباویژن، گوگل…)
  - iframe از دامنهٔ ثالث
  - لینک‌های `rel=sponsored`
  - بنرهای دارای UTM
  - برچسب «تبلیغات/آگهی»
  - رپورتاژ و پوش
- **جایگاه:** پاپ‌آپ، استیکی، هدر، بالای صفحه، داخل متن، بین فید، سایدبار، پایین صفحه، فوتر.
- **فرمت:** نیتیو، بنر، استیکی، اینترستیشال، ویدیو، متنی، رپورتاژ، همراه با سایز استاندارد IAB.
- **تبلیغ‌دهنده:** از لینک تبلیغ، داخل iframe یا پاسخ API شبکه پیدا می‌شود. اگر لینک نبود، از متن یا تصویر کریتیو با مدل vision رایگان شناسایی می‌شود. سطح رقابت و ورتیکال به‌صورت خودکار تعیین می‌شود. فایل `config/competitors.yaml` همیشه حرف آخر را می‌زند.
- **لندینگ:** مستقیم و بدون UTM باز می‌شود (بدون کلیک روی تبلیغ). نوع آن (محصول، دسته، کمپین، اپ، فرم) و آفرها (تخفیف، اقساط، ارسال رایگان، تایمر، کد تخفیف، گردونه) استخراج می‌شود.
- **فشار (0 تا 100):** اسلات در هر صفحه 30٪، تعداد تبلیغ‌دهنده 20٪، تراکم رقبا 25٪، سهم جایگاه ممتاز 10٪، چرخش کریتیو 15٪.
- **فرصت (0 تا 100):** دسترسی سایت 35٪، فشار پایین 35٪، حضور رقبا به‌عنوان اثبات مخاطب 15٪، قابل خرید بودن 15٪.
- **تهدید رقیب (0 تا 100):** SOV ورتیکال 35٪، رشد نسبت به ۷ روز 20٪، پوشش سایت‌ها 20٪، تهاجمی بودن (ریتارگتینگ، جایگاه ممتاز، پروموشن) 25٪.

## لیست سایت‌ها

- **شیت شما** همیشه اولویت دارد و در هر اجرا کامل اسکن می‌شود. فقط با تغییر شیت عوض می‌شود.
- **لیست سیستم** از `config/seed_publishers.yaml` شروع می‌شود و هر هفته از دو منبع گسترش پیدا می‌کند: رنکینگ Tranco (دامنه‌های ایرانی) و لینک‌های بین پابلیشرها.
  - سایت تازه اول با مدل زبانی بررسی می‌شود که پابلیشر محتوایی باشد، بعد تست می‌شود.
  - سایتی که تبلیغ داشته باشد «فعال» می‌شود.
  - سایتی که سه اسکن پیاپی تبلیغ نداشته باشد کنار می‌رود و ماه بعد دوباره امتحان می‌شود.
- برای حذف دائمی یک سایت، آن را در `exclude` همان فایل بنویسید.

## نگهداری داده

- دادهٔ خام (هر اسلات و اسکرین‌شات) **۳ روز** نگه داشته می‌شود.
- خلاصهٔ روزانه و اینسایت ماهانه **۳۱ روز** نگه داشته می‌شوند.
- دادهٔ سنگین در کش GitHub Actions می‌ماند تا حجم ریپو بالا نرود. فقط خلاصه‌ها و رجیستری‌ها (`data/daily`، `advertisers.json`، `publishers.json`، `inventory.json`، `creatives.json`) در ریپو ذخیره می‌شوند.

## تنظیمات رایج

| می‌خواهم… | کجا |
|---|---|
| گیرندهٔ ایمیل اضافه کنم | Secret با نام `MAIL_TO`، آدرس‌ها با کاما جدا شوند |
| رقیبی را قطعی کنم یا سطحش را عوض کنم | `config/competitors.yaml` |
| شبکهٔ تبلیغاتی جدید اضافه کنم | `config/ad_networks.yaml` (دامنه‌های پیشنهادی در تب «کشف» آمده‌اند) |
| تعداد سایت، پروفایل‌ها یا زمان اسکن را تغییر دهم | `config/settings.yaml` |
| ترتیب مدل‌ها را عوض کنم | Variable با نام `LLM_CHAIN`، مثلاً `gemini,github,groq,openrouter` |
| صفحهٔ عمومی منتشر نشود (فقط ایمیل) | Variable با نام `PUBLISH_PAGES` و مقدار `false` |
| همین الان گزارش بگیرم | Actions ← ad-radar ← Run workflow با تیک force_report |

## نکته‌ها

- ربات **هیچ‌وقت روی تبلیغ کلیک نمی‌کند**. هزینه‌ای برای تبلیغ‌دهنده ایجاد نمی‌شود و آمار کمپین‌ها آلوده نمی‌شود.
- اعداد **جهت‌دار** هستند، نه سهم دقیق بازار. هر اجرا نمونه‌ای از تبلیغات چرخشی است و دقت با گذشت روزها بالا می‌رود.
- ریپو و صفحهٔ گزارش عمومی هستند. هر کس آدرس را داشته باشد گزارش را می‌بیند. اگر این مشکل است، `PUBLISH_PAGES=false` را بگذارید تا گزارش فقط ایمیل شود. دادهٔ خلاصه در ریپوی عمومی همچنان دیده می‌شود.
- تست آفلاین: `python tests/run_offline.py` (با صفحات نمونه، بدون اینترنت).
